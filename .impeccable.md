## Design Context

### Users

Personal use — Mike + wife/family/friends. Two distinct contexts:

1. **New-tab page (desktop)** — quick capture while working. Opened dozens of times a day. Speed and frictionlessness are paramount; the app should get out of the way.
2. **PWA (mobile)** — both quick capture on the go and leisurely review (reading the list on the couch). Mobile needs full feature parity, not a stripped-down view.

Late-night use is common. The interface may be the last or first thing seen in a day.

### Brand Personality

Clear, focused, peaceful. A calm tool that respects your attention. More "quiet instrument" than "productivity app." Like jotting something on a notepad — effortless, personal, no ceremony.

Name: **Jot**

### Aesthetic Direction

- **Dark mode only** — warm OKLCH palette, low blue-light. Background `oklch(0.155 0.012 55)`. Light mode CSS exists but is dormant and not a design target.
- **Typographic identity**: DM Serif Display for the "JOT" wordmark (tracking `0.28em`), Figtree Variable for all body text.
- **Palette tokens**: `--hint` (`oklch(0.63 0.018 58)`) for secondary labels; `--ghost` (`oklch(0.38 0.014 55)`) for near-invisible affordances. Never use `text-[color]/[opacity]` for secondary colours — use these solid tokens instead.
- **Contrast floor**: `--hint` is the dimmest token used for readable text (5.6:1 on bg, 4.5:1+ on all surfaces). `--ghost` is for decorative/non-text affordances only — never use it for placeholder text or functional icon buttons. Contrast is a hard requirement — always verify new text tokens against their surface before shipping.
- **Primary**: `oklch(0.60 0.18 118)` — a warm, earthy green. The only real colour in the palette.
- **Background texture**: SVG fractal noise via `body::before` with `mix-blend-mode: soft-light`, dithering the gradient. Radial warm bloom from top + linear darkening from bottom (grounding).
- Minimal, unhurried. Clean desk, not a command center.
- Anti-references: loud productivity apps, gamified task managers, opacity-washed ghost UIs, anything that creates anxiety. Also: generic AI-generated UI (boxy cards, flat greys, default Tailwind aesthetics, anything that looks like it was templated).

### Categories

- Expected count: **3–5** (e.g. Work, Personal, etc.)
- Current pattern (horizontal tab row) is **under review** — may not scale to mobile or 5 categories gracefully.
- Critique pending: consider whether tabs, a dropdown, a sidebar pill list, or something else better fits the calm, personal aesthetic and works across mobile + desktop.

### Known Issues / Open Questions

- **"Floaty / lost" feeling** persists — content lacks sufficient visual anchoring. The warm gradient bloom and bottom-darkening gradient help but don't fully solve it. Needs further grounding work (possibly layout structure, stronger baseline, or a more intentional use of negative space).
- **Category navigation on mobile** — horizontal scroll of tabs is problematic on small screens. `/adapt` pass needed.

### Design Principles

1. **Respect the hour** — dark, warm, low-stimulus. No bright accents that jar at 2am.
2. **Disappear when not needed** — chrome should fade; the task list is the interface.
3. **Instant capture** — typing a task should feel frictionless, like thinking out loud.
4. **Calm clarity** — hierarchy through spacing and weight, not colour or decoration.
5. **Personal, not corporate** — this is a home tool, not a SaaS dashboard.
6. **Grounded, not floating** — content must feel anchored to a surface, not adrift on a gradient. Structure and negative space should create a sense of place.
7. **Mobile is first-class** — PWA on mobile is a real use case (capture + review). No feature amputations; adapt the layout.
8. **Polished and distinctive** — every detail should look intentional. Avoid default aesthetics, generic spacing, or anything that reads as "AI-generated." Quality over novelty.

### Anti-Patterns (Discovered This Session)

- ❌ Opacity for colour variation (`text-foreground/50`) — use `--hint` / `--ghost` tokens instead
- ❌ Sync status as a tiny icon-only dot — needs label + touch target
- ❌ Inline-expanding panels that shift layout — use absolute-positioned overlays
- ❌ `width` animation on progress bars — use `scaleX` transform
- ❌ Category colour swatches from generic palettes — must be warm-toned and harmonise with background
